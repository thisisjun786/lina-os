# Required OmO Native tool

Date: 2026-09-06. Status: mandatory inclusion planned; packaging details pending.
Parent: [Lina OS design](000_design.md).

Install OmO Native as a required, independently managed Lina OS development tool.
Lina currently owns coding work through Codex; no OmO job adapter is shipped.
Lina owns assistant identity, permanent conversations, memory and job results. OmO workers
are task executors, not replacements for the persistent user-facing agents.

## Installation and execution

- Pin OmO Native and its compatible integration version in the installation manifest.
- Include it in update, rollback and diagnostic inventory.
- Verify executable availability and the supported integration handshake during setup.
  Installation alone is not proof that a coding job can run.
- Resolve supported model/auth configuration with the selected provider setup. Avoid
  requiring a duplicate login when supported credential reuse is available; do not
  assume credentials or APIs are interchangeable.
- Start workers when delegated work needs them. Mandatory installation does not imply
  an always-running OmO daemon or a required OmO Desktop application.
- Propagate the Lina OS autonomous execution profile through supported worker settings;
  verify actual behavior rather than assuming the parent policy controls every child.

Each delegated job records agent/conversation IDs, workspace, execution host, job ID,
status and terminal result. Any future integration must forward progress and
cancellation through Lina-owned task contracts and pass a consumer compatibility
test. Preserve dirty work and coordinate concurrent writers. On uncertain worker
failure, reconcile state before resubmitting; deduplicate completion delivery.

Development installation and execution stay inside the Lina OS VM. Physical-server
deployment follows the existing transition plan. No current-host installation or
provider change is authorized by this documentation update.

## Acceptance additions

| ID | Scenario | Required result |
| --- | --- | --- |
| D01 | Fresh setup | Pinned executable and integration handshake available |
| D02 | Provider setup | Required worker route configured without assumed credential compatibility |
| D03 | Development integration check | Disposable coding job returns a real artifact to the original Lina conversation |
| D04 | Stop or worker failure | Cancellation/reconciliation reaches the worker; no duplicate resubmission |
| D05 | Autonomous OS profile | Supported worker execution does not add unintended approval prompts |
| D06 | Update/restart | Version compatibility and job/state continuity checked |

D03–D06 are development/release integration checks, not user-machine model benchmarks.
Include packaging in delivery stage 040. Determine exact commands and adapter contracts
from the pinned OmO source during implementation planning. Do not recreate retired
OmO job packages or introduce a second job engine merely to satisfy mandatory
installation. Integration scenarios remain future work.
